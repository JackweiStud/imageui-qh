以下核心模块已开发完成并合并至主分支，具备上线标准：

    *   创建 `generations` 表，每次生成自动保存记录到云端。

    *   历史记录云端同步功能（跨设备/清缓存恢复）。
    *   **核心风险已解决**: 用户已付费生成的图片不会丢失。

## 2. 🚀 MVP 上线待办清单 (Roadmap)
*按优先级 P0 -> P1 -> P2 排序*

### 🔴 P0: 核心阻断性问题 (必做)
*无法交付或存在严重数据丢失风险，必须修复。*

#### 1. [x] ~~历史记录云端化 (Supabase Database)~~ ✅ 已完成
*   **实现方式**: 混合模式（本地 IndexedDB + 云端 `generations` 表）
    *   每次生成后自动写入 Supabase `generations` 表
    *   提供"同步云端"按钮，用户可主动拉取云端记录
    *   网络错误时自动从云端恢复
*   **核心风险已解决**: 图片不会因切换设备/清缓存而丢失
*   **详细文档**: 参见 `docs/picFix.md`
*   **完成日期**: 2025-12-12

#### 2. [ ] Vercel 函数超时规避 (Timeout Mitigation)
*   **现状**: API 采用同步等待 (`await generateContent`)。Gemini 处理复杂任务常需 15-20s，而 Vercel Hobby (免费版) 限制 **10s**，导致必现 `504 Gateway Timeout`。
*   **风险**: 用户扣了分但拿不到图（此时后端还在跑，前端已断开）。
*   **方案 (选其一)**:
    *   **方案A (零代码/付费)**: 升级 Vercel Pro ($20/mo)，超时上限提升至 60s。这是最快路径。
    *   **方案B (代码/免费)**: 改造 API 为 **Streaming (流式响应)** 模式。虽然图片是二进制，但可以通过定期发送 "Processing..." 数据包保持 HTTP 连接不断开，直到最后发送图片 URL。
*   **工作量**: 小 (方案B 约 1 天)。

---

### 🟠 P1: 稳定性与运维 (强建议)
*如果不做，上线后可能面临难以排查的客诉。*

#### 3. [ ] 错误监控 (Sentry)
*   **现状**: 错误仅输出到 `console.error`，生产环境用户遇到白屏开发者无法感知。
*   **方案**: 接入 Sentry (Free Tier)。
*   **工作量**: 极小 (30分钟)。

#### 4. [x] 移动端适配微调
*   **现状**: 核心功能在 PC 端正常，移动端上传/生成流程部分 UI 可能存在溢出或交互不便。
*   **方案**: 针对手机浏览器进行一轮走查修复。
*   **工作量**: 小 (1 天)。

---

### 🟡 P2: 商业化闭环 (可延后)
*初期用户量小，可暂缓支持或使用替代方案。*

#### 5. [ ] 在线支付 (Stripe/LemonSqueezy)
*   **现状**: 目前仅能通过改数据库送积分。
*   **替代方案**: MVP 阶段可采用 "联系客服充值" 或 "邀请裂变送积分" 的人工运营方式。
*   **工作量**: 中 (3-5 天)。

#### 6. [ ] 异步任务队列 (Async Queue)
*   **现状**: 即使解决了超时，高并发下 Serverless 仍不稳定。
*   **方案**: 引入 Trigger.dev 或 Inngest 做真正的后台任务。
*   **决策**: 初期并发低，暂不需要引入此复杂度。
